# ⚠️  ملاحظة هامة جداً:
#   إذا لم تعمل نقرات القائمة المنسدلة في لوحة Render،
#   استخدم التوجيه المباشر عبر شريط العنوان للمسارات التالية:
#     • /environment  → متغيرات البيئة
#     • /settings     → إعدادات الخدمة
#     • /deploys      → عمليات النشر
#     • /crons        → مهام Cron الجدولية
#     • /logs         → سجلات التشغيل

# ═══════════════════════════════════════════════════════════════
# الخطوة 1 — حذف الخدمة القديمة (erp-system بنظام Docker)
# ═══════════════════════════════════════════════════════════════
1. افتح المتصفح واذهب إلى: https://dashboard.render.com
   (يجب أن تكون جلسة الدخول مفعلة مسبقاً)
2. من القائمة اليسرى → اختر "Services"
3. ابحث عن الخدمة باسم "erp-system" (Runtime = Docker)
4. اضغط عليها لفتح صفحة تفاصيلها
5. في أعلى اليمين → اضغط على الـ 3 نقاط (⋮) → اختر "Settings"
   (أو اذهب مباشرة إلى المسار: /settings داخل الصفحة)
6. انزل لأسفل الصفحة حتى تجد قسم "Danger Zone" أو "Delete Service"
7. اضغط على زر "Delete" واتبع التعليمات للتأكيد (قد يطلب كتابة اسم الخدمة)
8. انتظر حتى يختفي الخدمة تماماً من قائمة Services

# ═══════════════════════════════════════════════════════════════
# الخطوة 2 — إنشاء خدمة ويب جديدة (Node.js Runtime)
# ═══════════════════════════════════════════════════════════════
1. من لوحة التحكم الرئيسية → اضغط على زر "New +" في الأعلى
2. اختر "Web Service" من القائمة
3. ستظهر صفحة اختيار الريبو:
   • اختر "Connect account" لحساب GitHub إن لم يكن متصلاً
   • ابحث عن الريبو: infogolog11-debug/erp-system
   • اضغط على "Connect" بجانبه
4. صفحة الإعدادات — املأ كالتالي:
   ┌──────────────────────────────────────────────────────────────┐
   │ Name:              erp-system                               │
   │ Runtime:           Node                                     │
   │ Region:            Oregon (US West)                         │
   │ Branch:            main                                     │
   │ Plan:              Free                                     │
   │ Build Command:     npm install && npm run build             │
   │ Start Command:     node src/db/migrations/run-migrations.cjs && (node src/db/seed-production.cjs || true) && npm start
   └──────────────────────────────────────────────────────────────┘
5. اضغط على "Create Web Service" في الأسفل
6. **لا تنتظر** — انتقل فوراً إلى الخطوة 3 قبل أن يبدأ الـ Build

2. قسم "Environment Variables" → اضغط على "Add Variable" وأضف واحدة واحدة:

   │                      │ postgres?sslmode=require                     │
   │                      │                                             │
   │                      │ ⚠️  انسخ القيمة الكاملة من أسفل هذه الوثيقة │
   ├──────────────────────┼─────────────────────────────────────────────┤
   │ NODE_ENV             │ production                                  │
   ├──────────────────────┼─────────────────────────────────────────────┤
   │ AUTH_SECRET          │ GIbjpeeN7i0iEBInnBXbarsPgxvVXjL4aLcnwrugnYU=│
   ├──────────────────────┼─────────────────────────────────────────────┤

# ═══════════════════════════════════════════════════════════════
# الخطوة 4 — انتظار اكتمال الـ Build (مدة تقديرية: 8-15 دقيقة)
# ═══════════════════════════════════════════════════════════════
1. اذهب إلى تبويب "Deploys" في صفحة الخدمة
   (أو المسار المباشر: /deploys)
2. شاهد التقدم — سيظهر Build in Progress باللون الأصفر
3. أثناء انتظارك:
   • افتح تبويب "Logs" لرؤية سجلات الـ Build المباشرة
   • إذا ظهرت أخطاء حمراء → انسخها وعلقها لي لحلها
4. علامات الاكتمال الناجحة:
   ✅ يظهر آخر Deploy مع الحالة "Live" وثميلة خضراء
   ✅ في الـ Logs تظهر رسائل:
     - "🚀 بدء تشغيل الـ Migrations..."
     - "✅ جميع الـ Migrations تمت بنجاح!"
     - "🌱 بذر بيانات الإنتاج الأساسية..."
     - "✅ تم إعداد بيانات الإنتاج الأساسية بنجاح!"
     - "READY server started on port 10000" (أو أي منفذ آخر)
5. **انسخ الرابط العام للخدمة** من أعلى الصفحة
   (سيكون شكله: https://erp-system-xxxxxx.onrender.com)
   → الصقه في مكان آمن — ستحتاجه في الخطوة التالية

# ═══════════════════════════════════════════════════════════════
# الخطوة 5 — تحديث AUTH_URL و NEXT_PUBLIC_APP_URL وإعادة التشغيل
# ═══════════════════════════════════════════════════════════════
1. اذهب إلى تبويب Environment (المسار: /environment)
2. ابحث عن المتغيرين الآتيين وعدّل قيمهما:

   ┌─────────────────────────────────────────────────────────────┐
   │ Key                  │ Value                                │
   ├──────────────────────┼──────────────────────────────────────┤
   │ AUTH_URL             │ https://erp-system-xxxxxx.onrender.com│
   │                      │ (بدون شرطة مائلة في النهاية)         │
   ├──────────────────────┼──────────────────────────────────────┤
   │ NEXT_PUBLIC_APP_URL  │ https://erp-system-xxxxxx.onrender.com│
   │                      │ (نفس القيمة أعلاه تماماً)            │
   └─────────────────────────────────────────────────────────────┘

3. اضغط على "Save Changes"
4. Render سيقوم تلقائياً بإعادة تشغيل الخدمة (Redeploy)
5. انتظر حتى تعود الحالة إلى "Live" مع النقطة الخضراء
   (مدة التحديث: 2-3 دقائق فقط — لا يحتاج build جديد)

# ═══════════════════════════════════════════════════════════════
# الخطوة 6 — إنشاء Cron Job 1: erp-audit-integrity-check
# ═══════════════════════════════════════════════════════════════
1. من لوحة التحكم الرئيسية → اضغط على "New +" → اختر "Cron Job"
2. اختر نفس الريبو: infogolog11-debug/erp-system
3. اضغط "Continue"
4. صفحة الإعدادات — املأ كالتالي:
   ┌──────────────────────────────────────────────────────────────┐
   │ Name:              erp-audit-integrity-check                │
   │ Runtime:           Node                                     │
   │ Region:            Oregon (US West)                         │
   │ Branch:            main                                     │
   │ Plan:              Free                                     │
   │ Schedule:          0 3 */3 * *                              │
   │   (معنى: كل 3 أيام عند الساعة 3:00 صباحاً UTC)             │
   │ Build Command:     npm install                              │
   │ Start Command:     npm run audit:verify                     │
   └──────────────────────────────────────────────────────────────┘
5. اضغط على "Create Cron Job"
6. فوراً اذهب إلى تبويب Environment لهذا Cron
   (المسار المباشر: /crons/اسم-cron/environment)
7. أضف متغيرات البيئة التالية:
   ┌──────────────────────────────────────────────────────────────┐
   │ DATABASE_URL    ← نفس القيمة الدقيقة للخدمة الرئيسية       │
   │ NODE_ENV        ← production                                │
   └──────────────────────────────────────────────────────────────┘
8. احفظ التغييرات — سيعيد بناء الـ Cron تلقائياً

# ═══════════════════════════════════════════════════════════════
# الخطوة 7 — إنشاء Cron Job 2: erp-stock-reconcile
# ═══════════════════════════════════════════════════════════════
1. كرر نفس خطوات الخطوة 6 مع هذه الاختلافات:
   ┌──────────────────────────────────────────────────────────────┐
   │ Name:              erp-stock-reconcile                      │
   │ Schedule:          30 3 */3 * *                             │
   │   (معنى: كل 3 أيام عند الساعة 3:30 صباحاً UTC)             │
   │ Start Command:     npm run stock:reconcile                  │
   └──────────────────────────────────────────────────────────────┘
2. Environment Variables → نفس متغيرات Cron الأولى بالضبط:
   DATABASE_URL + NODE_ENV=production
3. احفظ التغييرات

# ═══════════════════════════════════════════════════════════════
# الخطوة 8 — تشغيل Cron Jobs يدوياً والتحقق من النجاح
# ═══════════════════════════════════════════════════════════════
لكل Cron من الاثنين (قم بهذا مع الأول ثم الثاني):
1. افتح صفحة الـ Cron (من قائمة Crons في اللوحة الرئيسية)
2. في أعلى الصفحة → اضغط على الزر "Run Now"
3. انتظر حتى ينتهي التشغيل (1-3 دقائق لكل cron)
4. تحقق من قسم "Last Run" في نفس الصفحة:
   ✅ يجب أن يظهر: "Success" باللون الأخضر
   ❌ إذا ظهر "Failed" → افتح تبويب Logs وأرسل لي الخطأ
5. كرر نفس الخطوات مع Cron الثاني

# الخطوة 9 — التحققات النهائية في المتصفح
# ═══════════════════════════════════════════════════════════════
# 📌 ملاحظة هامة: الخدمة على الخطة المجانية تتوقف بعد 15 دقيقة
#    من السكون، وطلب الأول سيحتاج ~50 ثانية (Cold Start).
#    لا تقلق — هذا سلوك طبيعي للخطة المجانية.
# ═══════════════════════════════════════════════════════════════

# --- 9-أ) فحص نقطة الصحة Health Check ---
1. افتح في المتصفح:  https://{رابط_الخدمة}/api/health
   مثال: https://erp-system-abc123.onrender.com/api/health
2. انتظر ~50 ثانية (Cold Start) حتى يستجيب السيرفر
3. يجب أن تحصل على رد JSON مثل هذا (HTTP 200):
   {
     "status": "ok",
     "timestamp": "2026-09-19T...",
     "database": { "connected": true, "latencyMs": ... },
     "version": "0.1.0"
   }
4. ✅ إذا ظهر status: "ok" → الانتقال للخطوة التالية
   ❌ إذا ظهر خطأ → انتظر دقيقة ثم أعد المحاولة، أو ارسل لي لقطة الشاشة

# --- 9-ب) تسجيل دخول المدير ---
1. افتح: https://{رابط_الخدمة}/login
2. سجل الدخول باستخدام:
   ┌─────────────────────────────────────────┐
   │ البريد الإلكتروني:  admin@yourorg.com │
   │ كلمة المرور:        2ANRMNTWNPeyXr8w39iZW3EU!1A. │
   └─────────────────────────────────────────┘
3. اضغط "تسجيل الدخول"
4. ✅ يجب أن يتم إعادة التوجيه تلقائياً إلى: /dashboard
   ❌ إذا ظهر خطأ في كلمة المرور → تأكد من إضافة SEED_ADMIN_PASSWORD
     في Environment Variables وأن الـ Seed قد نُفذ بنجاح (راجع Logs)

# --- 9-ج) التحقق من صفحة مستخدمي الإعدادات ---
1. بعد الدخول بنجاح → من القائمة اليسرى اختر Settings → Users
   أو اذهب مباشرة إلى: /dashboard/settings/users
2. ✅ يجب أن تظهر قائمة المستخدمين مع صف واحدة على الأقل:
   • admin@yourorg.com  • الدور: super_admin  • الحالة: نشط
